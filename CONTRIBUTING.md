# Contributing

Спасибо за интерес к проекту `iptv-ru-monitor`!

## Как внести изменения

1. Сделайте fork и создайте ветку: `feat/my-feature` или `fix/my-bugfix`.
2. Настройте окружение:
   ```bash
   uv sync --extra dev
   ```
3. Внесите изменения и добавьте тесты. Новый код должен покрывать сценарии,
   описанные в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
4. Перед коммитом проверьте локально:
   ```bash
   uv run ruff check .
   uv run ruff format --check .
   uv run mypy
   uv run pytest
   ```
   CI выполняет те же проверки на каждый Pull Request.
5. Создайте Pull Request с описанием: что изменено, почему и как проверено.

## Соглашения

- **Коммиты** — Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`.
- **Python** — 3.12+, типизация аннотациями, проверяется mypy.
- **Тесты** — pytest; сетевые проверки в тестах имитируются (без реальных запросов).
- **Безопасность** — новые URL-источники добавляются только со статусом `review`
  и записью в реестре источников (см. [docs/SOURCE_POLICY.md](docs/SOURCE_POLICY.md)).

## Добавление нового источника IPTV

1. Проверьте лицензию и условия использования источника.
2. Опишите источник в `config/sources.yaml` с `public_policy: review`.
3. Если формат отличается от M3U — реализуйте адаптер `SourceAdapter` в
   `src/iptv_monitor/discovery/` и добавьте фикстуру в `tests/fixtures/`.
4. Убедитесь, что секретные токены в URL не попадут в артефакты и логи.

## Чего мы не принимаем

- Ссылки на потоки, обходящие DRM/авторизацию/платные подписки.
- Секретные или временные токены в конфигурации и тестах.
- Изменения, публикующие источники с неясными правами без записи в реестре.
