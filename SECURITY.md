# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 0.1.x  | исправления безопасности |

## Как сообщить об уязвимости

Напишите на адрес, указанный в настройках репозитория GitHub (Security advisories),
или откройте приватный отчёт через вкладку **Security → Report a vulnerability**.

Не создавайте публичный issue с деталями уязвимости. Мы ответим в течение 7 дней.

## Модель угроз

Проект выполняет запросы к **недоверенным сторонним URL**. Принятые меры:

- **SSRF-защита** — запрещены обращения к localhost, приватным, link-local и
  служебным IP-диапазонам; проверяется каждая цепочка редиректов.
- **Редакция логов** — токены, ключи и приватные параметры URL маскируются.
- **Публикация** — секретные URL не попадают в публичные артефакты (`streams.json`,
  `report.json`, M3U); источники с токенами отклоняются политикой публикации.
- **VDS** — отдельный пользователь без root, минимально привилегированный SSH-ключ CI,
  ограничения CPU/памяти/времени, запрет выполнения команд, полученных из данных
  источников (см. [deploy/vds/README.md](deploy/vds/README.md)).
- **Секреты** — только в GitHub Actions Secrets, никогда в коде и конфигурации.

## Что не является уязвимостью

- Наличие публично доступных потоков в каталоге (мы не управляем источниками).
- Геоблокировка потоков со стороны правообладателей.
